# Autonomous Capability Builder

## Trigger
Use when a task exposes a repeated missing capability, unreliable step, provider dependency, or manual bottleneck.

## Build loop
1. Detect the gap.
2. Search existing open-source implementations and standards.
3. Verify the strongest sources.
4. Define the smallest reusable contract.
5. Implement the skill/tool/adapter in the correct repository.
6. Add a self-test or verification procedure.
7. Record limitations and fallback behavior.
8. Register the capability in operating memory.
9. Re-run the original task using the new capability.
10. Keep only evidence-backed claims of success.

## Independence test
A new capability is valuable when it reduces future dependence on paid SaaS, manual intervention, undocumented memory, or one fragile provider without violating terms.

## Anti-patterns
- copying a README and calling it a capability;
- adding a provider without testing its current availability;
- claiming autonomous operation when a human approval is still required;
- mixing project-specific code into the generic skill repository.
